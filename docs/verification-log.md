## 2026-11-08 지원 회사 이름이 커밋에 들어간 문제

- 증상: 지원 회사 이름이 커밋 메시지 2개와 파일 7개(공고 폴더 이름, 예시 실행의 공고 분석, 테스트 경로, 결정 기록)에 들어갔다. 테스트용 샘플 공고 문장도 실제 공고 문장을 그대로 썼다.
- 발견한 곳: 사람(사용자 검토). 원인 층: 지침. "개인 자료는 커밋하지 않는다"는 규칙에 회사 이름이 포함되는지 정의되어 있지 않았다.
- 조치:
  - push 전이라 `git filter-branch`로 커밋 7개의 파일과 메시지를 모두 다시 썼다. 공고 폴더는 `job-001`로 바꾸고, 예시 실행의 공고 분석 파일은 삭제했으며, 테스트 샘플 공고는 지어낸 문장으로 바꿨다.
  - 예전 참조와 reflog를 지우고 gc를 실행했다. 예전 커밋이 남아 있지 않음을 `git cat-file`로 확인했다.
- 재발 방지: 이름 목록을 `data/private_terms.json`(git 제외)에 두고, `tests/test_no_private_terms.py`가 커밋 대상 파일과 모든 커밋 메시지를 검사한다. CLAUDE.md 규칙에 명시했다.
- 재검증: 모든 커밋 트리를 `git grep`으로 검사한 결과 0건, 메시지 검사도 0건, 테스트 55개 통과.
- **검사 장치 자체의 빈틈 (바로 이어서 발견)**: 검사 테스트의 예시 문장에 실제 회사 이름이 들어 있었다. 커밋 전 실행에서는 이 파일이 아직 git 추적 전이라 검사 대상(`git ls-files`)에서 빠졌고, 커밋 후 다시 돌렸을 때 실패했다. 예시를 가상의 이름으로 바꾸고, 추적 전인 새 파일(`--others --exclude-standard`)도 검사하도록 고쳤다. 해당 커밋은 push 전 마지막 커밋이라 amend로 기록에서 지웠다.
- 남은 한계: 문자열 포함 검사라서 짧은 이름이 일반 단어 안에 들어 있으면 거짓 실패가 날 수 있다(예: 다른 단어의 일부).

## 2026-11-08 Figma 빌더: 사용자 ZIP 규칙 반영과 선 회전 부호

- 요구: 1920×1080, 기본 레이어만(Text·Rectangle·Ellipse·Line), 화살표도 Line, Vector·SVG 금지, 이미지는 Rectangle 채우기, ZIP에 미리보기 없음.
- 기존 빌더와의 차이: Ellipse 없음, 화살표 없음, 선은 오른쪽·아래 방향만 가능.
- 문서 확인(공식 Figma Plugin API):
  - LineNode의 끝 모양(strokeCap)은 양쪽 끝에 함께 적용되고, 한쪽만 지정하는 방법은 문서에 없다 → 화살촉을 짧은 Line 2개로 만들었다.
  - `rotation = Math.atan2(-m10, m00)` → 화면 좌표에서 아래로 향하는 선은 음수 회전이어야 한다. 기존 런타임은 `+atan2`라 세로선과 대각선이 반대(위쪽)로 그려졌을 가능성이 있다.
- 원인 층: 코드(기존 빌더). 지금까지는 가로선만 써서 드러나지 않았던 것으로 추정한다.
- 조치: 테스트 9개를 먼저 쓰고 실패를 확인한 뒤 구현했다. 테스트 64개 통과. 네 방향 화살표와 원을 미리보기로 그려 눈으로 확인했다.
- **미검증**: Figma에서 실제로 같은 방향으로 그려지는지. `samples/figma-orientation-check.json`으로 확인해야 한다.
