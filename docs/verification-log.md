## 2026-11-08 검사 도구: 테스트 먼저 작성

- 구현 전에 테스트 6개 파일 작성(인용 일치·제외·수치 출처·글자 수·PDF/docx 추출·실행 로그). 오류 사례 포함: 인용 한 글자 변조, 핵심 업무 2개, 중복 인용, 공고에 없는 역량명, 지어낸 수치(95%), 같은 숫자 다른 단위(120명↔120건), 글자 수 초과, 한글·공백 경로.
- 구현 전 실행 결과: `5 errors during collection` (`ModuleNotFoundError: check_analysis` 등). Step 0에서 먼저 만든 `log.py`만 수집됨. 이 상태로 `test:` 커밋.

## 2026-11-08 검사 도구 구현

- 구현 후 49개 테스트 통과.
- **실제 자료로 돌려 보다 발견한 문제**: 행별 대표 포트폴리오 PDF 6개와 자소서 4개를 `extract_text.py`로 추출했다. 그런데 Figma에서 내보낸 PDF는 `2 0 2 6 . 0 1`처럼 숫자 사이에 공백이 들어간다.
  - 발견 위치: 실행(추출 결과를 사람이 직접 열어 봄). 원인 층: 입력(PDF 텍스트 레이어) + 코드(수치 검사가 이 형태를 가정하지 않음).
  - 영향: 원천 자료에 실제로 있는 날짜·수치도 "출처 없음"으로 판정된다(거짓 실패).
  - 조치: 실제 사례를 테스트로 먼저 추가 → 실패 확인 → 원천 자료의 숫자 사이 공백을 합치도록 수정 → 50개 통과.
  - 남은 한계: 글자 사이 공백(`RA G`, `Languag e`)도 있다. 인용 검사는 공백을 무시하므로 영향이 없고, 수치 검사는 숫자만 다룬다.

**에이전트가 스스로 보고한 확인 필요 사항** (자료끼리 충돌. 코드가 아니라 에이전트가 찾았고, 사람이 판단할 일이라 추천서에 넘김):
- Notion 한 페이지 안에서 대회 본선 수치가 두 가지로 적혀 있음.
- 포트폴리오의 판정 수와 Notion 커밋 설명의 수가 다름(서로 다른 것을 센 수치인지 확인 필요).
- 같은 프로젝트가 Notion에 두 페이지로 있음(하나는 제목에 "기각"). 사용자 지시에 따라 v2만 사용.
- 자소서 파일 이름과 내용이 일부 다름(두 회사 답변이 한 파일에 있음).

아직 검증하지 않은 것: 추천의 질(사람이 확인), 수치 출처 검사(초안 단계에서 실행), 제작 단계.
