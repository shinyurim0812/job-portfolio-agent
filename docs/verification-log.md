# 검증 기록

오류·확인 항목마다: 증상/질문 → 발견한 곳 → 원인이 있던 층 → 조치 → 재검증.

## 2026-11-08 Step 0: 서브에이전트 동작 확인

만들기 전에 오케스트레이션 전제가 실제로 성립하는지 먼저 확인했다. 시험 에이전트 2개(probe-a, probe-b)를 한 메시지에서 동시에 호출했다.

| 확인 항목 | 결과 | 근거 |
|---|---|---|
| 병렬 실행 | 성립 | `tools/log.py`가 찍은 시각: probe-b 02:11:59.9–02:12:18.2, probe-a 02:12:00.2–02:12:20.3 → 구간이 겹침. 시각은 에이전트가 쓴 값이 아니라 스크립트가 기록 |
| 서브에이전트의 Notion MCP 접근 | 성공 (2/2) | 각 에이전트가 `notion-get-self` 호출 결과를 data/step0/*.json에 기록 |
| 저장소 밖(상위 폴더) 파일 읽기 | 성공 (2/2), 권한 창 없음 | 같은 파일 |
| 에이전트별 모델 지정 | 성공 | Agent 호출의 `model` 옵션: probe-a=Haiku 5.5, probe-b=Sonnet 5.5로 자기 보고 |
| 세션 도중 만든 `.claude/agents/*.md` 인식 | **실패** | `Agent type 'step0-probe' not found`. 에이전트 목록은 세션 시작 시 고정됨 |

- 원인 층: 도구(Claude Code) 동작.
- 조치: 이번 세션에서는 오케스트레이터가 `.claude/agents/<name>.md`를 읽어 그 내용을 범용(general-purpose) 에이전트에 넘기고 `model`을 지정한다. 새 세션에서는 파일로 정의한 에이전트가 그대로 인식되는지 에이전트 목록으로 확인한다.
- 부수 확인: 자동 모드 분류기가 `.claude/settings.json`(권한 허용 목록) 생성을 "자기 설정 변경"으로 거부했다. 자동 모드에서 시험 에이전트가 권한 창 없이 끝까지 실행되었으므로 이 파일 없이 진행한다.
